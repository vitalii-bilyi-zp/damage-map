# Загальний опис інформаційної системи "Damage Map"

## 1. Вступ

Інформаційна система "Damage Map" (далі — Система) є веб-орієнтованим програмним комплексом, призначеним для обліку, візуалізації та аналізу пошкоджень інфраструктурних об'єктів на території України. Система забезпечує централізоване збирання даних про пошкодження, їх геопросторову візуалізацію та статистичний аналіз.

## 2. Призначення та мета системи

### 2.1. Основне призначення

Система призначена для вирішення наступних завдань:

1. **Облік пошкоджень інфраструктури** — систематизований збір та зберігання інформації про пошкоджені об'єкти з детальним описом характеристик пошкоджень.

2. **Геопросторова візуалізація** — відображення даних про пошкодження на інтерактивній карті з можливістю фільтрації за різними критеріями (регіон, район, громада, тип об'єкта).

3. **Аналітична підтримка прийняття рішень** — надання статистичних даних та OLAP-аналітики для оцінки масштабів пошкоджень та планування відновлювальних робіт.

4. **Прогнозування вартості відновлення** — автоматичний розрахунок орієнтовної вартості відновлювальних робіт на основі моделі машинного навчання.

5. **Документальний супровід** — зберігання та надання доступу до нормативних актів, що регулюють процеси відновлення.

### 2.2. Цілі створення системи

- Забезпечення єдиного інформаційного простору для обліку пошкоджень інфраструктури
- Підвищення прозорості та оперативності збору даних про пошкодження
- Автоматизація процесу оцінки вартості відновлення
- Надання аналітичних інструментів для планування відновлювальних робіт
- Забезпечення публічного доступу до агрегованої статистики пошкоджень

## 3. Основні функціональні можливості

### 3.1. Модуль візуалізації (Інтерактивна карта)

Центральним елементом системи є інтерактивна карта на базі Mapbox GL, яка забезпечує:

- **Багаторівневу візуалізацію** — відображення даних на рівні регіонів, районів та територіальних громад з автоматичним перемиканням при зміні масштабу
- **Теплову карту пошкоджень** — градієнтне забарвлення територій відповідно до сумарної вартості відновлення
- **Фільтрацію даних** — можливість фільтрації за категорією та типом об'єкта
- **Інформаційні вспливаючі вікна** — відображення детальної інформації при кліку на територіальну одиницю

### 3.2. Модуль управління даними про пошкодження

Забезпечує повний цикл роботи з даними про пошкодження:

- **Внесення свідчень** — публічна форма для подання інформації про пошкодження громадянами
- **Workflow схвалення** — процес модерації поданих свідчень (очікує → схвалено/відхилено)
- **Редагування записів** — можливість коригування даних адміністраторами
- **Імпорт даних** — завантаження даних з Excel/CSV файлів
- **Експорт даних** — вивантаження даних у CSV форматі

### 3.3. Модуль статистики та аналітики

Надає інструменти для аналізу даних:

- **Глобальна статистика** — динаміка пошкоджень за часовими періодами (день/тиждень/місяць)
- **Співвідношення за типами** — розподіл пошкоджень за типами об'єктів
- **OLAP-куб** — багатовимірний аналіз даних за різними вимірами:
  - Часові виміри: день, тиждень, місяць
  - Географічні виміри: регіон, район, громада
  - Класифікаційні виміри: категорія об'єкта, тип об'єкта, ступінь пошкодження

### 3.4. Модуль прогнозування вартості відновлення

Інтеграція з зовнішнім мікросервісом машинного навчання (Flask API) для:

- **Автоматичного прогнозування** — розрахунок орієнтовної вартості відновлення при створенні/редагуванні запису
- **Врахування множини факторів** — тип об'єкта, площа, поверховість, ступінь пошкодження, регіон, тип ремонту

### 3.5. Модуль управління нормативними документами

- Завантаження та зберігання нормативних актів (PDF)
- Публічний доступ до документів
- Управління переліком документів (додавання/видалення)

### 3.6. Модуль віртуальних турів

Забезпечує створення та перегляд мультимедійного контенту:

- Створення віртуальних турів з різними типами контенту (текст, зображення, слайдер)
- Публічний перегляд турів

### 3.7. Модуль управління користувачами

- Реєстрація та автентифікація користувачів
- Рольова модель доступу
- Прив'язка користувачів до територіальних одиниць

## 4. Цільові користувачі та їх ролі

### 4.1. Неавторизовані користувачі (публічний доступ)

**Доступні функції:**
- Перегляд інтерактивної карти пошкоджень
- Перегляд статистики та OLAP-куба
- Перегляд нормативних документів
- Перегляд віртуальних турів
- Подання свідчень про пошкодження (створення заявки)

### 4.2. Роль "Analyst" (Аналітик)

**Призначення:** Базова роль для авторизованих користувачів з обмеженими правами.

**Доступні функції:**
- Всі функції неавторизованого користувача
- Перегляд списків схвалених та нерозглянутих заявок

### 4.3. Роль "Admin" (Адміністратор)

**Призначення:** Регіональний адміністратор з правами модерації даних у межах призначеної території.

**Доступні функції:**
- Всі функції аналітика
- Перегляд та редагування записів про пошкодження
- Схвалення/відхилення заявок на внесення даних
- Експорт даних у CSV

**Територіальне обмеження:** Адміністратор має доступ лише до даних, що належать до призначеного йому регіону, району або громади.

### 4.4. Роль "Super Admin" (Суперадміністратор)

**Призначення:** Системний адміністратор з повним доступом до всіх функцій.

**Доступні функції:**
- Всі функції адміністратора без територіальних обмежень
- Управління користувачами (створення, редагування, видалення)
- Управління нормативними документами
- Управління віртуальними турами
- Імпорт даних з файлів

## 5. Характеристики предметної області

### 5.1. Географічна ієрархія

Система оперує трирівневою адміністративно-територіальною ієрархією України:

```
Регіон (Region)
    └── Район (District)
            └── Територіальна громада (Community)
```

### 5.2. Класифікація об'єктів

Пошкоджені об'єкти класифікуються за дворівневою схемою:

```
Категорія об'єкта (Object Category)
    └── Тип об'єкта (Object Type)
```

### 5.3. Ступені пошкодження

Система використовує трирівневу шкалу ступенів пошкодження:

| Код | Назва | Опис |
|-----|-------|------|
| `low` | Легке | Незначні пошкодження |
| `medium` | Середнє | Помірні пошкодження |
| `high` | Тяжке | Значні пошкодження |

### 5.4. Типи ремонту

Класифікація видів відновлювальних робіт (`RepairType`), що використовується для уточнення прогнозу вартості.

## 6. Основні сутності даних

### 6.1. Запис про пошкодження (DamageNote)

Центральна сутність системи, що містить:

| Атрибут | Опис |
|---------|------|
| `date` | Дата фіксації пошкодження |
| `object_type_id` | Тип пошкодженого об'єкта |
| `community_id` | Територіальна громада |
| `city` | Населений пункт |
| `street` | Вулиця |
| `building_number` | Номер будинку |
| `floors` | Кількість поверхів |
| `area` | Площа (м²) |
| `damage_type` | Ступінь пошкодження |
| `repair_type_id` | Тип ремонту |
| `restoration_cost` | Фактична вартість відновлення |
| `predicted_restoration_cost` | Прогнозована вартість відновлення |
| `comment` | Коментар |

### 6.2. Заявка на внесення даних (DamageNoteRequest)

Сутність для workflow схвалення:

| Атрибут | Опис |
|---------|------|
| `full_name` | ПІБ заявника |
| `email` | Email заявника |
| `phone` | Телефон заявника |
| `damage_note_id` | Пов'язаний запис про пошкодження |
| `approved_at` | Дата схвалення |
| `declined_at` | Дата відхилення |
| `approver_comment` | Коментар модератора |

## 7. Висновки

Інформаційна система "Damage Map" є комплексним рішенням для обліку та аналізу пошкоджень інфраструктури, що поєднує:

- Сучасний веб-інтерфейс з інтерактивною картографією
- Гнучку систему управління даними з workflow модерації
- Потужні аналітичні інструменти включно з OLAP-аналізом
- Інтеграцію з системою машинного навчання для прогнозування
- Рольову модель доступу з територіальними обмеженнями

Система забезпечує як публічний доступ до агрегованих даних, так і контрольований доступ для адміністрування даних, що робить її ефективним інструментом для координації зусиль з відновлення пошкодженої інфраструктури.
